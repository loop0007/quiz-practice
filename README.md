# 在线刷题网站

基于本地题库的 React 单页应用：题库选择、答题判分、错题复习、收藏、历史成绩、主题壁纸、动态特效与 PWA 离线。纯前端，无后端依赖，可部署为静态站点。

- 公网地址：https://loop0007.github.io/quiz-practice/
- 题库：Java 218 题（1 章）、Web 118 题（6 章），共 336 道有效题
- 测试：90 项单元测试、206 项无头浏览器检查
- 状态：核心功能、额外功能与 UI 美化已完成；Linux/WSL 实测与真机蜂窝验收待补

## 设计思路

### 目标与场景

- 目标用户：在校学生与自学者，用本地题库完成日常练习和错题复习。
- 熄灯后的宿舍：深色模式使用深棕底色而非纯黑，降低亮度但不牺牲文字对比度。
- 床上或地铁里的手机：主要操作放进拇指可达区域，触控目标不小于 44px，底部操作栏适配安全区，题号使用抽屉而非横向挤压。
- 桌面浏览器：保留完整文字导航、题号侧栏和键盘快捷键，长题干与代码块有足够宽度。
- 本地优先：不要求登录，不依赖后端，关闭页面后练习记录仍在；同一份构建产物既能本地静态托管，也能部署到 GitHub Pages。

### 信息架构

- 练习主链路：首页 → 题库列表 → 题库内侧筛选 → 答题页 → 结果页。
- 复习支线：结果页可直接错题重练；错题本按题库分组重练；收藏夹与历史成绩从顶栏进入。
- 答题页把“选题、提交、翻题、交卷”集中在同一屏；桌面用右侧题号栏，移动端收进底部抽屉，避免频繁跳页。
- 错题本、收藏夹默认按题库分组收起，减少长列表噪音；进入批量管理时自动展开，避免操作前提不明确。

### 视觉与交互

- 视觉采用暖米色纸感背景、深棕正文、宋体标题与橙色强调，区别于常见蓝白题库界面；深色模式复用同一套 token 反相。
- 状态不只依赖颜色：答对/答错同时使用图标与文字，题号状态配合颜色和标记，弱色觉用户仍可判断。
- 动效服务于层级而非炫技：首次进入整页模糊软聚焦，首页文字与按钮错峰淡入上移，页面切换淡入，卡片悬停轻微上浮。
- 所有动效都响应 `prefers-reduced-motion`；触屏不触发悬停位移，避免移动端“粘住”的悬停态。
- 移动端顶栏隐藏品牌文字，把首页、题库、历史、错题、收藏直接露出；低频工具保留在“三”菜单，减少主界面占用。

### 技术架构

- 题库 Markdown 在开发和构建前由 `scripts/parse-banks.mjs` 转为 `src/data/banks.json`，缺题干、缺答案、答案不在选项等异常题单独统计且不进入练习。
- 页面按 `pages → components → store → lib` 分层；页面不直接操作 Dexie 表，判分与统计只在 `lib/scoring.ts` 中实现，避免多处口径漂移。
- 练习开始时把本轮题目 ID 冻结进 Session，后续统计、重练和结果页都以该快照为准；题号使用 `bankId:questionNo`，避免两套题库从 1 开始造成冲突。
- 练习过程状态由 Zustand 管理，Dexie/IndexedDB 负责会话、错题、收藏、反馈和自定义壁纸；主题、壁纸与特效选择写入 localStorage。
- 路由使用 HashRouter，Vite `base: './'`，静态托管到任意子路径都不需要 rewrite；生产构建后由脚本生成 Service Worker，实现离线打开。
- 测试分两层：Vitest 覆盖解析、判分、持久化与派生逻辑；playwright-core 调用本机 Edge/Chrome 覆盖桌面与 375/390 移动视口、深浅色和完整业务流程。

### 关键取舍

- 每题首次提交后锁定，重复点击幂等；未作答按错误计入正确率，并进入错题重练。
- 异常题不计入分母；结果页单独展示异常题数，避免“题目本身有问题”影响成绩。
- 错题记录答对后仍保留，强调“曾经错过的题”而不是“当前错误集合”；需要清理时可批量移出。
- 本期不做账号、云同步、排行榜与运行期题库上传；跨设备数据不同步是明确的产品边界，而不是待修缺陷。
- 不使用后端数据库：练习记录保存在浏览器 IndexedDB，首次访问后即可离线使用。

### 项目结构

```text
src/pages        页面编排（首页、题库、答题、结果、错题本、收藏、历史）
src/components   布局、题卡、题号导航、弹窗、折叠分组等展示组件
src/store        Zustand 练习状态
src/lib          题库读取、判分、Dexie、主题、壁纸、特效、快捷键
src/data         parse-banks.mjs 生成的 banks.json
scripts          题库解析、来源检查、Service Worker 生成、浏览器验收
docs             测试记录、开发计划与验收截图
题库             原始 Markdown 题库
```

## 功能

### 练习

- **首页**：题库总量、章节数、本机练习进度，进度卡保持紧凑，仅提供“去题库开始”入口。
- **题库列表**：使用整行条形卡片展示题量、题型构成、章节数与异常题数；点击卡片进入题库内侧。
- **筛选练习**：按章节与单选/多选/判断组合筛选，实时显示可练习题数；开始后冻结本轮题目快照。
- **继续练习**：未交卷的练习收为“继续上次练习”按钮，保留原进度；也可重新开始新一场。
- **答题**：题干、选项、行内代码与代码块正常渲染；逐题提交后立即判分并锁定，显示正确答案与解析。
- **翻题与导航**：上一题/下一题、已答/答对进度、桌面题号侧栏、移动端题号抽屉，状态用颜色加图标/文字区分。
- **交卷**：有未提交题时先提示数量并二次确认；结果页展示总题数、已答、答对、答错、未答、正确率与异常题数。
- **错题重练**：结果页把本轮答错与未作答的题冻结为新一轮独立练习，独立计分并进入历史成绩。
- **键盘快捷键**：字母键按选项 key、数字键 1–9 按顺序选择，Enter 提交，← / → 翻题；输入框与弹窗内不触发。

### 复习与记录

- **错题本**：跨练习累计，按题库分组并默认收起；点击题库标题展开题目，也可一键展开/收起全部。题目卡展示题干、你的答案、正确答案、解析与首次答错时间，支持批量勾选、全选与移出。进入批量管理时自动展开全部分组。
- **分组重练**：错题本按题库把累计错题生成独立练习；入口按钮显示“重练”且不显示题数，题目失效时自动剔除，答对后仍保留错题记录。
- **收藏夹**：答题页可收藏/取消收藏，刷新后保持；按题库分组展示，支持逐个取消与批量取消，取消入口位于题目卡头部。
- **历史成绩**：已交卷练习按时间倒序排列，汇总练习次数、累计答对与平均正确率，可进入对应结果页。
- **反馈**：题目反馈支持答案错误、选项缺失、解析错误、建议、其他；主页反馈支持建议与其他。记录保存到本机 IndexedDB，不依赖网络。

### 外观与体验

- **导航与菜单**：桌面端保持品牌文字、文字导航与“三”菜单；移动端隐藏品牌文字，首页、题库、历史、错题、收藏五个入口直接放在顶栏，“三”菜单继续提供使用说明、下载为应用、外观、反馈与深色模式。
- **深色模式**：跟随系统 / 浅色 / 深色三态切换，选择写入 localStorage，首屏不闪白。
- **壁纸**：云霞（内置图片）、晨曦、暮色、青野四套壁纸，也可上传本机图片（最大 5 MB）；自定义图片存 IndexedDB，刷新后恢复。
- **动态特效**：关闭、樱花飘落、动态线条、粒子动画四种效果，可叠加任意壁纸；同一时间只启用一种，默认关闭。移动端自动减少数量，系统开启“减少动态效果”时停用。
- **动效**：首次进入整页从轻微放大与模糊中柔和显现；首页标题与按钮错峰淡入上移；页面切换复用同一动画；卡片悬停上浮并增强阴影。触屏不触发悬停，减少动态效果时取消位移。
- **移动端与无障碍**：底部固定操作栏适配安全区，主要触控目标不小于 44px；原生表单控件、焦点样式、`aria-live` 判分提示与可跳过的正文入口。
- **PWA 离线与安装**：生产构建生成 Manifest 与 Service Worker，首次访问后离线仍可打开并开始练习；“三”菜单中的“下载为应用”提供自动安装（支持的浏览器）或手动添加到主屏幕的说明。

### 数据边界

- 练习记录、错题、收藏、反馈、自定义壁纸存 IndexedDB；主题、壁纸与特效选择存 localStorage。
- 数据按浏览器与 origin 隔离，手机与电脑之间不同步；换设备相当于从零开始。
- 本期不做账号、云端同步、排行榜、成就，也不支持运行时上传或解析题库。

## 页面流

首页 → 题库列表 → 题库内侧（章节/题型筛选 + 开始练习）→ 答题页（收藏 + 题号导航 + 提交/交卷）→ 结果页 → 错题重练 / 错题本（分组重练） / 收藏夹 / 历史成绩。

## 运行方式

> **不能直接双击 `index.html`**（源码和 `dist/` 都不行），必须通过 HTTP 访问。项目是纯前端，**不需要数据库服务**，数据保存在浏览器 IndexedDB / localStorage。
>
> **依赖**：Node.js 20.19+ 或 22.12+、npm 10+，首次 `npm install` 需联网；浏览器验收另需本机 Chrome 或 Edge。

### 开发模式

```bash
npm install
npm run dev -- --host
```

打开 `http://localhost:5173`。`--host` 让同一 Wi-Fi 下的手机也能访问。

### 构建与预览

```bash
npm install
npm run build
npm run preview -- --host
```

打开 `http://localhost:4173`。产物在 `dist/`，可部署到任意静态托管。

不使用 Vite 时，可用静态服务器托管 `dist/`：

```bash
npm run build
python3 -m http.server -d dist 8080   # Windows: py -m http.server -d dist 8080
```

打开 `http://localhost:8080`。

### 检查与测试

```bash
npm test              # 单元/数据测试
npm run check:source  # 调试残留、空链接、import 大小写
npm run test:e2e      # 自动构建并启动 preview，跑浏览器验收
```

`test:e2e` 会自动查找 Edge/Chrome；找不到时用 `EDGE_PATH="浏览器路径" npm run test:e2e` 指定。

**提示**：端口被占用时 Vite 会自动换端口，以终端输出为准；离线能力只在 `localhost` 或 HTTPS 下生效；Linux 下 import 路径区分大小写。

## 判分与数据口径

- 每题只提交一次，以第一次提交计入成绩；重复点击不改变结果。
- 单选/判断要求选项集合完全一致；多选要求集合相等，少选、多选、顺序不同均判错。
- 只有提交才计入已答；未作答按错误计入正确率，也会进入错题重练。
- 正确率分母为本轮有效题数；异常题不进入练习，也不计入分母。
- 结果页“本次错题”只统计本轮；错题本跨练习累计。
- 题目 ID 为 `bankId:questionNo`；每轮练习保存 `questionIds` 快照，统计以快照为准。
- 题库 JSON 只由脚本生成并校验；页面不直接操作 Dexie 表，判分只在 `scoring.ts` 实现。

### 真实修正记录

#### 工程与题库

- 首次异常题检测未覆盖全部题目，补做第二次全量检测后确认有效题与异常题清单。

- Markdown 选项保留前导空白导致多余空行，改为 `trim`；多行代码选项直接按预格式文本渲染，避免原始 `<` 被当作 HTML。
- 首次 Git 提交因本机未配置作者信息失败，后续提交显式指定作者。
- 静态检查脚本最初误报：生成题库 JSON 中的 `console.log` 被当作调试残留，`http://` 中的 `p:/` 被当作 Windows 盘符；改为跳过生成文件、排除 URL 协议后通过。

#### 存储、判分与答题

- 移动端题号抽屉初版标题重复、图例被裁切，改为抽屉固定标题 + 题号网格内部滚动。
- 预览服务器缓存旧脚本导致抽屉改动未生效，验收脚本禁用缓存后复测通过。
- E1 浏览器验收发现：完成一场练习后，在同一 SPA 会话中回到首页开始新练习，答题页首帧仍读到 store 里上一场已交卷的 session，直接重定向到旧结果页；改为只有 `session.id` 与路由一致时才视为当前会话，否则按加载中处理。
- E5 验收时发现既有 e2e 检查存在异步竞态：`sr-only` 单选输入只有 1×1 像素，偶发点不中；错题本/收藏夹在数据加载完成前就断言条目数。改为点击可见 label 并确认勾选，断言前等待条目或按钮出现。
- E6 离线验收首次失败：导航能离线打开，但 JS/CSS 报 `net::ERR_FAILED`。排查发现 Vite preview 返回 `Vary: Origin`，预缓存时的请求与页面发起模块脚本请求的 `Origin` 头不一致，导致 `caches.match` 未命中；改为匹配缓存时传入 `ignoreVary: true` 后离线整站可渲染。
- U1 信息架构调整后，旧 e2e 的“历史成绩”链接选择器同时匹配新首页的“查看历史成绩”文案，Playwright strict mode 报多元素；为导航链接加 `exact: true`，并按新路由把选题、筛选与菜单操作改为经题库列表进入题库内侧 / 先打开“三”菜单。
- U1 视觉复核发现原生 `<dialog>` 被 Tailwind preflight 的全局 `margin: 0` 覆盖，弹窗贴在左上角；为使用说明、题号、外观与反馈弹窗补 `m-auto` 恢复居中（底部抽屉保持 `m-0`）。
- 分组默认收起、页面过渡动画等改动曾让既有 e2e 的时序假设失效，出现等待 `article` 超时或按钮断言过早；通过先展开分组、补充 `waitFor` 修正测试，而不是改业务逻辑迁就测试。
- 收敛按钮文案与选择器时，错题本入口从“错题组卷”改为“重练”，同步更新桌面与移动端 e2e 选择器、按钮文本断言和文档，避免测试仍以旧文案通过。
- 题库卡片从两列改整行条形时，首次替换没有匹配到仓库当前内容（HEAD 中还有一段题量说明）；重新读取文件后按实际内容替换，避免误删信息。

#### 布局、触控与动效

- 无头浏览器检查发现主题按钮仅 36px 宽，补足 44px 触控目标。
- 移动端顶栏五个导航入口首轮只有 38px 宽，未达到 44px 触控要求；定位为右侧动作容器按内容收缩，给容器补充 `min-w-0 flex-1 md:flex-none` 后等分剩余空间，并复跑触控断言。

### 协作约定

1. 每次只完成当前指定的功能，不擅自扩展需求。
2. 只读取当前任务所需的文件，避免重复扫描整个项目。
3. 优先复用现有代码和组件，无必要不重写文件。
4. 修改前确认相关依赖，尽量一次完成同一功能涉及的修改。
5. 只运行与本次修改相关的测试，必要时再进行完整测试。
6. 修改完成后，简要列出修改的文件、实现的功能和测试结果，不重复输出完整源代码。
7. 同一错误连续修复两次仍失败时，停止修改并先分析原因。
8. 保持项目结构清晰，将重要架构决策简要记录在项目文档中。
9. 每次请求都简洁明了地解释请求内容。
10. README 和 plan 需要同步实现更新。

### 验证与边界

- 每轮改动以自动化结果为准：单元/数据测试、浏览器验收、静态检查、类型检查与构建全部通过后才更新“已完成”描述。
- AI 不能替代真实设备验收：Linux/WSL 从零安装、手机蜂窝网络和另一台电脑的访问仍需人工完成，已在“尚未完成”中保留。
