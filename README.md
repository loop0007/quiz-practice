# 在线刷题网站

> 基于本地题库的在线刷题网站。目前已实现题库选择、答题、判分、结果页、错题本、反馈、章节/题型筛选与移动端/深色体验基线；已通过 GitHub Pages 部署公网 HTTPS 地址。阶段三测试已完成 T1–T4，阶段四完成 E1（当前 60 项单元/数据测试、74 项无头浏览器检查）；T5 的 Linux 实测与真机验收仍待完成。

## 设计思路

### 目标与场景

- 目标用户：在校学生。
- 核心场景（验收下限，不是加分项）：
  - 熄灯后的宿舍：低亮度下可读，支持深色模式。
  - 床上使用手机：单手可操作，触控目标足够大。
  - 地铁上单手扶栏杆：能完成选题、作答、翻题。
  - 桌面浏览器：完整功能与题号侧栏。
- 界面参考：[Lucide 图标](https://lucide.dev/icons/)、[Mobbin 移动端案例](https://mobbin.com/)、[牛客网布局](https://www.nowcoder.com/)。

### 功能范围

一期核心（先保证完整跑通）：

- 题库加载与选择（Java、Web 两套）。
- 按章节/题型筛选练习：题库卡片提供筛选入口，可只练某一章节，或任选单选、多选、判断的组合；确认后按筛选结果冻结题目快照开始新练习。
- 题目与选项展示；逐题提交（选择后点“提交答案”，提交即判分并锁定该题），全部完成后可直接交卷；存在未提交题时先提示数量，再次确认后才交卷。
- 上一题 / 下一题；答题进度；实时显示已答、答对数。
- 题号侧栏：未做白、正确绿、错误红，同时配合图标/文字标识。
- 交卷结果页：总题数、已答/答对/答错/未答、正确率（未作答按错误计入）、题库异常题数，以及本次错题与未作答题号。
- 答题记录自动保存；错题本跨多次练习累计，按题库分组，展示题干、你的答案、正确答案、解析与首次答错时间。
- 同题不可重复提交，以第一次结果为准；只要曾经答错就进入错题本。
- 反馈：答题页每题有“反馈”入口，主页也有通用反馈入口；题目反馈可选答案错误/选项缺失/解析错误/建议/其他，主页反馈可选建议/其他，并可填写备注；记录只保存在本机 IndexedDB，不依赖网络。
- 移动端：答题页底部固定操作栏（题号、上一题、提交、下一题、交卷），适配安全区；题号导航改为底部抽屉；主要触控目标不小于 44px。
- 深色模式：跟随系统 / 浅色 / 深色三态切换，选择写入本机 localStorage；首屏内联脚本先行应用主题，刷新不闪白。

二期（有余力再做）：

- 收藏夹、壁纸与主题切换、历史成绩统计、错题组卷练习。
- 后端管理

本期不做：
- PWA 离线、键盘快捷键。
- 账号、云端同步、排行榜、成就。
- 运行期上传/解析题库。
### 页面流

题库选择 → 答题页（题号侧栏 + 上一题/下一题 + 提交/交卷）→ 结果页 → 错题本（历史成绩为二期）。

### 关键设计

- 题目 ID 使用 `bankId:questionNo`：两套题库的题号都从 1 开始，不能只存题号。
- 题库在构建前由脚本转为 JSON 并校验；缺题干、缺答案、答案不在选项、重复题号等记为异常题；无有效答案的题不进入练习和正确率分母，结果页单独展示异常数。
- 答题状态以 Zustand 为唯一数据源，Dexie 负责持久化；各页面从同一份状态派生，避免判分不一致。
- 筛选练习只改变新 session 的 `questionIds` 快照，不改 Session 结构、判分与统计口径；筛选条件不写入数据库，结果页仍按快照统计。
- 答题页只把与路由 `sessionId` 一致的 store 会话当作当前会话，避免开始新练习时被上一场已交卷记录抢先重定向。
- 判分口径统一：每题只允许提交一次，以第一次提交结果计入成绩；重复点击不改变成绩；首次答错进入错题本；正确率分母为题库总题数，未作答按错误计；结果页的“本次错题”与错题本分开统计。
- 提交逻辑幂等：按 `bankId:questionNo` 检查是否已有提交记录，存在则直接返回，避免双击或重复点击写入第二次结果。
- 静态运行：Vite 设置 `base: './'`，路由使用 HashRouter，避免子路径部署与静态服务器的资源、深链接问题。
- 主题：偏好存 `localStorage` 的 `theme` 键（`system` / `light` / `dark`）；`index.html` 内联脚本在首屏绘制前应用 `.dark`，React 加载后由 `useThemeStore` 接管手动切换、持久化与系统外观变化。
- 移动端：底部操作栏使用 `env(safe-area-inset-bottom)`；题号抽屉为原生 `dialog`，最高 85dvh，题号网格内部滚动并保留状态图例，主要按钮不小于 44px。
- 题目文本含行内代码与代码块（如 `<video>`、`str.charAt(1)`），渲染时按文本/代码处理，不使用未消毒的 HTML 注入。

## AI 使用情况

> 只记录真实过程，保留失败与走弯路；开发时随手记录，不事后补写。

- 主要用途：工程脚手架与依赖配置、题库解析脚本、判分/统计纯函数、IndexedDB 持久化、答题页/结果页/错题本/反馈弹窗、单元测试、浏览器端到端验收与文档同步。
- 出现的错误：
  - 未找到到所有异常题目，进行第二次检测
  - TypeScript 7 不再支持 `baseUrl`，路径别名改为相对 `paths` 配置。
  - Vite 配置在 ESM 下使用 `__dirname` 产生告警，改用 `import.meta.dirname`。
  - 题库标题正则最初误匹配 `###`，调整为只识别“数字 + 点”的题号行。
  - `anomalyCount` 最初按异常记录条数统计，改为按异常题目去重计数。
  - Markdown 选项保留前导空白导致多余空行，改为 `trim`；多行代码选项直接按预格式文本渲染，避免原始 `<` 被当作 HTML。
  - 首次 Git 提交因本机未配置作者信息失败，后续提交显式指定作者。
  - 移动端题号抽屉初版标题重复、图例被裁切，改为抽屉固定标题 + 题号网格内部滚动。
  - 无头浏览器检查发现主题按钮仅 36px 宽，补足 44px 触控目标。
  - 预览服务器缓存旧脚本导致抽屉改动未生效，验收脚本禁用缓存后复测通过。
  - Netlify 首发站点默认 Private/SSO 访问，公网返回 401；按选定方案改用 GitHub Pages。
  - GitHub Pages 首次部署需在仓库 Settings → Pages 把 Source 设为 GitHub Actions，工作流本身不负责启用 Pages。
  - 按用户要求本地只提交版本、GitHub 手动推送与发布，工作流由 push 触发改为仅 `workflow_dispatch`。
  - 阶段三浏览器验收发现浏览器自动请求 `favicon.ico` 返回 404，在控制台留下报错；补 `public/favicon.svg` 并在 `index.html` 声明后复测通过。
  - 静态检查脚本最初误报：生成题库 JSON 中的 `console.log` 被当作调试残留，`http://` 中的 `p:/` 被当作 Windows 盘符；改为跳过生成文件、排除 URL 协议后通过。
  - E1 浏览器验收发现：完成一场练习后，在同一 SPA 会话中回到首页开始新练习，答题页首帧仍读到 store 里上一场已交卷的 session，直接重定向到旧结果页；改为只有 `session.id` 与路由一致时才视为当前会话，否则按加载中处理。
- 发现与验证方式：Vitest 覆盖判分、持久化、store、题库数据与章节/题型筛选（当前 60 项）；无头 Edge 端到端脚本（`npm run test:e2e`，74 项检查），走通选题→答题→提交→翻题→刷新恢复→交卷→结果→错题本→反馈，并检查 1280/375/390 布局、深色、触控尺寸、横向溢出、控制台报错与跨页面一致性；E1 追加判断题筛选流程（15 道）与筛选后首题一致性检查；另用 `npm run check:source` 检查 import 大小写、调试残留与空链接。M10 已用公网 curl 与无头 Edge 验证首页、JS/CSS 和 Hash 深链接，真机蜂窝与另一台电脑验收待完成。测试记录见 [docs/测试记录.md](docs/测试记录.md)。

## 运行方式

> 脚手架建立后按实际命令校正。验收会在 Linux 服务器上运行（考题要求），命令需跨平台，不依赖 Windows 路径。

- 环境要求：Node.js 20.19+ 或 22.12+、npm 10+。
- 安装依赖：`npm install`
- 本地开发：`npm run dev -- --host`
- 单元测试：`npm test`（60 项）
- 静态检查：`npm run check:source`（调试残留、空链接、import 大小写）
- 浏览器验收：`npm run test:e2e`（构建后自动启动 preview；需本机安装 Edge/Chrome，74 项检查）
- 测试记录：[docs/测试记录.md](docs/测试记录.md)
- 构建：`npm run build`（构建前会自动重新解析题库）
- 预览构建产物：`npm run preview -- --host`
- 访问地址：开发默认 `http://localhost:5173`，预览默认 `http://localhost:4173`。
- 交付时附带构建后的 `dist/`，验收机可用静态服务器直接运行，减少现场构建依赖。
- 说明：本项目是 Vite 单页应用，不能直接双击源码 `index.html`；需通过上述命令或静态服务器访问。交付构建产物时可用 `python3 -m http.server -d dist 8080`。
- Linux 注意：文件系统区分大小写，`import` 路径必须与文件名大小写一致；不要使用 Windows 专属路径或命令。

### 公网访问（手机 / 其他电脑）

- 公网地址：https://loop0007.github.io/quiz-practice/
- 托管平台：GitHub Pages（项目页子路径 `/quiz-practice/`），由 GitHub Actions 自动构建发布。
- 发布方式：本地只做 Git 提交，不自动推送或发布。需要更新线上站点时，由你手动 `git push origin main`，再到仓库 Actions 页面点击 **Run workflow**（`workflow_dispatch`）；[deploy.yml](.github/workflows/deploy.yml) 依次执行 `npm ci`、`npm test`、`npm run build` 并发布 `dist/`。
- 首次配置：仓库 Settings → Pages → Build and deployment → Source 选择 “GitHub Actions”；之后每次推送自动生效。
- 子路径兼容：`base: './'` + HashRouter，刷新 `#/practice/...` 这类深链接不会 404，无需服务端 rewrite。
- 本地复核：`npm run build` 后执行 `npm run preview -- --host`。
- 验证方式：手机**关闭 Wi-Fi 用蜂窝网络**打开网址，另一台电脑也打开一次，各完成一套练习。
- 数据说明：答题记录和错题本保存在浏览器 IndexedDB 中，按设备与 origin 隔离；手机、电脑、不同域名之间不会同步，换设备相当于从零开始（账号与云端同步不在本期范围）。
- 网络提示：GitHub Pages 在国内部分网络可能较慢或不可达；如验收网络访问不稳定，可把 `dist/` 另发布到腾讯 EdgeOne Pages 等国内静态托管，站点无需改代码。
