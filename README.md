# 在线刷题网站

> 基于本地题库的在线刷题网站。目前已实现首页、题库选择、答题、判分、结果页、错题本、收藏夹、历史成绩、错题重练、错题组卷、反馈、使用说明、章节/题型筛选、壁纸、键盘快捷键、PWA 离线与移动端/深色体验基线，并完成阶段五暖色纸感 UI；已通过 GitHub Pages 部署公网 HTTPS 地址。阶段三测试已完成 T1–T4，阶段四完成 E1–E7，阶段五完成 U1（当前 88 项单元/数据测试、157 项无头浏览器检查）；T5 的 Linux 实测与真机验收仍待完成。

### 功能范围

- 首页：展示题库总量、章节数与本机练习进度，提供去题库与历史成绩入口；题库入口位于顶部菜单。
- 题库加载与选择（Java、Web 两套）：题库列表只负责选择题库，点击卡片进入题库内侧。
- 按章节/题型筛选练习：筛选与“开始练习”都在题库内侧，可只练某一章节，或任选单选、多选、判断的组合；开始后按筛选结果冻结题目快照。
- 导航：桌面端为右上角文字导航（首页、题库、历史成绩、错题本、收藏夹）；“三”菜单在各端常驻，集中提供使用说明、外观、反馈与深色模式，移动端导航也收在该菜单中。
- 题目与选项展示；逐题提交（选择后点“提交答案”，提交即判分并锁定该题），全部完成后可直接交卷；存在未提交题时先提示数量，再次确认后才交卷。
- 上一题 / 下一题；答题进度；实时显示已答、答对数。
- 题号侧栏：未做白、正确绿、错误红，同时配合图标/文字标识。
- 交卷结果页：总题数、已答/答对/答错/未答、正确率（未作答按错误计入）、题库异常题数；本次错题与未作答默认只显示题数，点击“查看题号”弹出具体题号，可针对错题重练。
- 答题记录自动保存；错题本跨多次练习累计，按题库分组，展示题干、你的答案、正确答案、解析与首次答错时间；支持批量勾选、全选与移出错题本。
- 历史成绩：已交卷练习按交卷时间倒序展示，汇总已完成次数、累计答对与平均正确率（未答计入分母），可进入对应结果页。
- 错题重练：已交卷的结果页提供入口，把本轮所有未答对的题（答错 + 未作答）冻结为新一轮练习；新一轮是独立 session，独立计分并单独出现在历史成绩中，不影响原结果。
- 错题组卷：错题本按题库提供“错题组卷”入口，把该题库累计错题按题号排序冻结为新一轮独立练习；题目已失效（解析异常被排除）的错题不进入组卷，答对后仍保留错题本记录。
- 收藏夹：答题页顶部可收藏/取消收藏当前题，收藏状态刷新后保持；新增收藏夹页面按题库分组展示收藏题目与收藏时间，可逐条取消收藏，也支持批量勾选后取消收藏。收藏只保存在本机 IndexedDB。
- 作答口径：只有点击“提交答案”才计入已答；选了答案但没有提交（包括选了正确答案）仍算未作题，并会进入错题重练。
- 同题不可重复提交，以第一次结果为准；只要曾经答错就进入错题本。
- 使用说明：顶部“三”菜单内提供五步简明指引，不占用页面正文；反馈入口也收在同一菜单中。题目反馈可选答案错误/选项缺失/解析错误/建议/其他，主页反馈可选建议/其他，并可填写备注；记录只保存在本机 IndexedDB，不依赖网络。
- 移动端：答题页底部固定操作栏（题号、上一题、提交、下一题、交卷），适配安全区；题号导航改为底部抽屉；主要触控目标不小于 44px。
- 深色模式：跟随系统 / 浅色 / 深色三态切换，选择写入本机 localStorage；首屏内联脚本先行应用主题，刷新不闪白。
- 壁纸：首页“外观”入口提供晨曦、暮色、青野三套内置壁纸，也可上传本机图片（最大 5 MB）；选择存 localStorage，自定义图片存 IndexedDB，刷新后恢复。背景叠加深浅色半透明遮罩，保证正文对比度。
- 键盘快捷键：答题页支持字母键（按选项 key）与数字键 1–9 选择答案，Enter 提交，← / → 切换上一题/下一题；输入框、已打开的弹窗与题目锁定后自动忽略对应按键。
- PWA 离线：生产构建生成 Web App Manifest 与 Service Worker，首次访问后预缓存页面、脚本、样式、图标与题库数据；地铁等弱网/离线环境仍可打开站点并开始练习。开发模式不注册 Service Worker，避免干扰热更新。


本期不做：
- 账号、云端同步、排行榜、成就。
- 运行期上传/解析题库。
### 页面流

首页 → 题库列表 → 题库内侧（章节/题型筛选 + 开始练习）→ 答题页（收藏 + 题号侧栏 + 上一题/下一题 + 提交/交卷）→ 结果页 → 错题重练 / 错题本 → 错题组卷 / 收藏夹 / 历史成绩。

### 关键设计

- 阶段五只改视觉与组件结构：在 Tailwind `@theme` 中重映射 `slate` / `blue` 色阶，新增 surface、border、brand 与圆角/阴影 token，既有语义类名随主题变暖；路由拆为首页 `/`、题库列表 `/banks`、题库内侧 `/banks/:bankId`，不改 Session、判分与存储契约。
- 题目 ID 使用 `bankId:questionNo`：两套题库的题号都从 1 开始，不能只存题号。
- 题库在构建前由脚本转为 JSON 并校验；缺题干、缺答案、答案不在选项、重复题号等记为异常题；无有效答案的题不进入练习和正确率分母，结果页单独展示异常数。
- 答题状态以 Zustand 为唯一数据源，Dexie 负责持久化；各页面从同一份状态派生，避免判分不一致。
- 筛选练习只改变新 session 的 `questionIds` 快照，不改 Session 结构、判分与统计口径；筛选条件不写入数据库，结果页仍按快照统计。
- 答题页只把与路由 `sessionId` 一致的 store 会话当作当前会话，避免开始新练习时被上一场已交卷记录抢先重定向。
- 历史成绩只读取已交卷会话，按交卷时间倒序；汇总复用 `getSessionStats`，正确率按各次总题数累计、未答计入分母，与结果页口径一致。
- 错题重练只复用 `scoring.getRedoQuestionIds` 派生题目快照，并用 `createSession` 新建独立 session；不改 Session 字段、判分与存储。重练范围为本轮答错 + 未作答，保持原快照顺序；未提交的勾选只存在于页面草稿，不写入 session，因此选了正确答案但未提交仍算未作答。
- 错题组卷复用 `wrongbook.getWrongBookQuestionIds` 从错题本派生快照：按题库筛选、剔除题库中已不存在的题、按题号升序，再调用 `createSession` 生成独立 session；不改错题本记录，答对后记录仍保留。
- 收藏夹以 Dexie `version(2)` 新增独立的 `favorites` 表，既有 sessions/wrongBook/feedback 表结构不变；答题页通过 db API 读写收藏，不写入 Session。移动端主导航在窄屏隐藏文字标签、保留图标与 `aria-label`，为新增入口留出空间。
- 壁纸只通过根元素 CSS 变量 `--wallpaper-image` 与 `has-wallpaper` 类实现：内置壁纸为渐变，自定义图片为 data URL；选择存 localStorage，图片存 Dexie `version(3)` 的 `wallpapers` 表。背景叠加 0.27 透明度的深浅色遮罩，保留壁纸观感的同时维持正文对比度，页面结构与 Session/判分不参与。
- 键盘快捷键拆成纯函数 `resolvePracticeShortcut`：只把按键解析为选择/提交/翻题动作，DOM 事件、输入框与弹窗守卫留在页面，便于单测且不引入全局快捷键体系；已锁定题目忽略字母/数字与提交。
- Service Worker 由 `scripts/generate-sw.mjs` 在 `vite build` 后生成，预缓存清单与内容哈希自动更新，无需手改；只在 `import.meta.env.PROD` 下注册。导航请求网络优先、离线回退缓存的 `index.html`，静态资源缓存优先；匹配缓存时使用 `ignoreVary`，避免预览服务器的 `Vary: Origin` 导致预缓存资源命中失败。
- 判分口径统一：每题只允许提交一次，以第一次提交结果计入成绩；重复点击不改变成绩；首次答错进入错题本；正确率分母为题库总题数，未作答按错误计；结果页的“本次错题”与错题本分开统计。
- 提交逻辑幂等：按 `bankId:questionNo` 检查是否已有提交记录，存在则直接返回，避免双击或重复点击写入第二次结果。
- 静态运行：Vite 设置 `base: './'`，路由使用 HashRouter，避免子路径部署与静态服务器的资源、深链接问题。
- 主题：偏好存 `localStorage` 的 `theme` 键（`system` / `light` / `dark`）；`index.html` 内联脚本在首屏绘制前应用 `.dark`，React 加载后由 `useThemeStore` 接管手动切换、持久化与系统外观变化。
- 移动端：底部操作栏使用 `env(safe-area-inset-bottom)`；题号抽屉为原生 `dialog`，最高 85dvh，题号网格内部滚动并保留状态图例，主要按钮不小于 44px。
- 题目文本含行内代码与代码块（如 `<video>`、`str.charAt(1)`），渲染时按文本/代码处理，不使用未消毒的 HTML 注入。

## AI 使用情况

> 只记录真实过程，保留失败与走弯路；开发时随手记录，不事后补写。

- 主要用途：工程脚手架与依赖配置、题库解析脚本、判分/统计纯函数、IndexedDB 持久化、答题页/结果页/错题本/反馈弹窗、单元测试、浏览器端到端验收与文档同步。
- 出现的错误：
  - 未找到到所有异常题目，进行第二次检测
  - TypeScript 7 不再支持 `baseUrl`，路径别名改为相对 `paths` 配置。
  - Vite 配置在 ESM 下使用 `__dirname` 产生告警，改用 `import.meta.dirname`。
  - 题库标题正则最初误匹配 `###`，调整为只识别“数字 + 点”的题号行。
  - `anomalyCount` 最初按异常记录条数统计，改为按异常题目去重计数。
  - Markdown 选项保留前导空白导致多余空行，改为 `trim`；多行代码选项直接按预格式文本渲染，避免原始 `<` 被当作 HTML。
  - 首次 Git 提交因本机未配置作者信息失败，后续提交显式指定作者。
  - 移动端题号抽屉初版标题重复、图例被裁切，改为抽屉固定标题 + 题号网格内部滚动。
  - 无头浏览器检查发现主题按钮仅 36px 宽，补足 44px 触控目标。
  - 预览服务器缓存旧脚本导致抽屉改动未生效，验收脚本禁用缓存后复测通过。
  - Netlify 首发站点默认 Private/SSO 访问，公网返回 401；按选定方案改用 GitHub Pages。
  - GitHub Pages 首次部署需在仓库 Settings → Pages 把 Source 设为 GitHub Actions，工作流本身不负责启用 Pages。
  - 按用户要求本地只提交版本、GitHub 手动推送与发布，工作流由 push 触发改为仅 `workflow_dispatch`。
  - 阶段三浏览器验收发现浏览器自动请求 `favicon.ico` 返回 404，在控制台留下报错；补 `public/favicon.svg` 并在 `index.html` 声明后复测通过。
  - 静态检查脚本最初误报：生成题库 JSON 中的 `console.log` 被当作调试残留，`http://` 中的 `p:/` 被当作 Windows 盘符；改为跳过生成文件、排除 URL 协议后通过。
  - E1 浏览器验收发现：完成一场练习后，在同一 SPA 会话中回到首页开始新练习，答题页首帧仍读到 store 里上一场已交卷的 session，直接重定向到旧结果页；改为只有 `session.id` 与路由一致时才视为当前会话，否则按加载中处理。
  - E5 验收时发现既有 e2e 检查存在异步竞态：`sr-only` 单选输入只有 1×1 像素，偶发点不中；错题本/收藏夹在数据加载完成前就断言条目数。改为点击可见 label 并确认勾选，断言前等待条目或按钮出现。
  - E6 离线验收首次失败：导航能离线打开，但 JS/CSS 报 `net::ERR_FAILED`。排查发现 Vite preview 返回 `Vary: Origin`，预缓存时的请求与页面发起模块脚本请求的 `Origin` 头不一致，导致 `caches.match` 未命中；改为匹配缓存时传入 `ignoreVary: true` 后离线整站可渲染。
  - U1 信息架构调整后，旧 e2e 的“历史成绩”链接选择器同时匹配新首页的“查看历史成绩”文案，Playwright strict mode 报多元素；为导航链接加 `exact: true`，并按新路由把选题、筛选与菜单操作改为经题库列表进入题库内侧 / 先打开“三”菜单。
  - U1 视觉复核发现原生 `<dialog>` 被 Tailwind preflight 的全局 `margin: 0` 覆盖，弹窗贴在左上角；为使用说明、题号、外观与反馈弹窗补 `m-auto` 恢复居中（底部抽屉保持 `m-0`）。
- 发现与验证方式：Vitest 覆盖判分、持久化、收藏夹、壁纸读写、键盘快捷键解析、store、题库数据、章节/题型筛选、历史成绩汇总、错题重练与错题组卷题目派生（当前 88 项）；无头 Edge 端到端脚本（`npm run test:e2e`，157 项检查），走通首页→题库列表→题库内侧→答题→提交→翻题→刷新恢复→交卷→结果→错题本→反馈，并检查 1280/375/390 布局、深色、触控尺寸、横向溢出、控制台报错与跨页面一致性；E1 追加判断题筛选流程（15 道）与筛选后首题一致性检查；E2 追加历史成绩汇总、结果页跳转与移动端空状态检查；E3 追加错题组卷入口、题数、独立 session、答对后成绩与错题本记录保留检查；E4 追加答题页收藏、刷新保持、收藏夹展示与取消收藏、移动端空状态检查；E5 追加内置壁纸应用与刷新保持、自定义图片上传/刷新/移除、非图片拒绝与移动端弹窗检查；E6 追加键盘选择/提交/翻题、弹窗阻断与离线刷新后开始练习检查；E7 追加错题重练入口、题数、独立 session 与原结果不受影响检查；U1 追加首页统计、题库列表无开始按钮、点击卡片进入题库内侧与内侧开始按钮、“三”菜单入口、使用说明弹窗、结果页题号弹窗、错题本/收藏夹批量勾选与题库内侧无重复统计卡片检查；另用 `npm run check:source` 检查 import 大小写、调试残留与空链接。M10 已用公网 curl 与无头 Edge 验证首页、JS/CSS 和 Hash 深链接，真机蜂窝与另一台电脑验收待完成。测试记录见 [docs/测试记录.md](docs/测试记录.md)。

## 运行方式

> 脚手架建立后按实际命令校正。验收会在 Linux 服务器上运行（考题要求），命令需跨平台，不依赖 Windows 路径。

- 环境要求：Node.js 20.19+ 或 22.12+、npm 10+。
- 安装依赖：`npm install`
- 本地开发：`npm run dev -- --host`
- 单元测试：`npm test`（88 项）
- 静态检查：`npm run check:source`（调试残留、空链接、import 大小写）
- 浏览器验收：`npm run test:e2e`（构建后自动启动 preview；需本机安装 Edge/Chrome，157 项检查）
- 测试记录：[docs/测试记录.md](docs/测试记录.md)
- 构建：`npm run build`（构建前会自动重新解析题库）
- 预览构建产物：`npm run preview -- --host`
- 访问地址：开发默认 `http://localhost:5173`，预览默认 `http://localhost:4173`。
- 交付时附带构建后的 `dist/`，验收机可用静态服务器直接运行，减少现场构建依赖。
- 说明：本项目是 Vite 单页应用，不能直接双击源码 `index.html`；需通过上述命令或静态服务器访问。交付构建产物时可用 `python3 -m http.server -d dist 8080`。
- Linux 注意：文件系统区分大小写，`import` 路径必须与文件名大小写一致；不要使用 Windows 专属路径或命令。

### 公网访问（手机 / 其他电脑）

- 公网地址：https://loop0007.github.io/quiz-practice/
- 托管平台：GitHub Pages（项目页子路径 `/quiz-practice/`），由 GitHub Actions 自动构建发布。
- 发布方式：本地只做 Git 提交，不自动推送或发布。需要更新线上站点时，由你手动 `git push origin main`，再到仓库 Actions 页面点击 **Run workflow**（`workflow_dispatch`）；[deploy.yml](.github/workflows/deploy.yml) 依次执行 `npm ci`、`npm test`、`npm run build` 并发布 `dist/`。
- 首次配置：仓库 Settings → Pages → Build and deployment → Source 选择 “GitHub Actions”；之后每次推送自动生效。
- 子路径兼容：`base: './'` + HashRouter，刷新 `#/practice/...` 这类深链接不会 404，无需服务端 rewrite。
- 本地复核：`npm run build` 后执行 `npm run preview -- --host`。
- 验证方式：手机**关闭 Wi-Fi 用蜂窝网络**打开网址，另一台电脑也打开一次，各完成一套练习。
- 数据说明：答题记录和错题本保存在浏览器 IndexedDB 中，按设备与 origin 隔离；手机、电脑、不同域名之间不会同步，换设备相当于从零开始（账号与云端同步不在本期范围）。
- 网络提示：GitHub Pages 在国内部分网络可能较慢或不可达；如验收网络访问不稳定，可把 `dist/` 另发布到腾讯 EdgeOne Pages 等国内静态托管，站点无需改代码。
